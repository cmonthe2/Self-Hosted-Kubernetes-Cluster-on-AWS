# Self-Hosted Kubernetes Cluster on AWS

Terraform provisions the AWS infrastructure; Ansible configures the nodes end-to-end.

```
AWS VPC
 ├── Public subnet  → control-plane (t3.medium, Ubuntu 22.04)
 └── Private subnet → worker × N   (t3.medium, Ubuntu 22.04)
```

**Stack:**
`Terraform 1.8+` · `AWS provider 5.x` · `kubeadm 1.30` · `containerd` · `Calico CNI`

---

## Prerequisites

The only thing you need locally is git. All tooling (Terraform, Ansible, Python) runs inside GitHub Actions.

Before triggering your first workflow you need:
- An AWS account with an S3 bucket + DynamoDB table for Terraform state
- An EC2 key pair (used by Ansible to SSH into nodes)
- GitHub Secrets configured (see below)

---

## Deployment (GitHub Actions)

Everything runs through GitHub Actions — no local Terraform or Ansible needed.

### 1 — Configure GitHub Secrets and Variables

Go to **Settings → Secrets and variables → Actions** in your repo.

**Secrets** (sensitive values):

| Secret name | Value |
|-------------|-------|
| `AWS_ROLE_ARN` | ARN of the IAM role GitHub OIDC will assume (see [OIDC setup](#aws-oidc-setup)) |

That's it. No SSH key, no CIDR, no key pair name. Terraform handles all of it:
- The **SSH key pair** is generated by Terraform and the private key stored in SSM Parameter Store
- The **allowed SSH CIDR** is resolved at runtime from the GitHub Actions runner's own public IP

**Variables** (non-sensitive):

| Variable name | Example value | Notes |
|---------------|--------------|-------|
| `TF_VAR_WORKER_COUNT` | `2` | Number of worker nodes |
| `SSM_KEY_PATH` | *(leave blank)* | Only set this if you override `project_name` or `environment` in `variables.tf`. Default: `/k8s-cluster-dev/ssh-private-key` |

### 2 — AWS OIDC Setup

Create an IAM OIDC identity provider for GitHub and a role that trusts it. The role needs permissions to manage VPC, EC2, IAM, S3, and DynamoDB (for state).

```bash
# Quick reference — run once in your AWS account
aws iam create-open-id-connect-provider \
  --url https://token.actions.githubusercontent.com \
  --client-id-list sts.amazonaws.com \
  --thumbprint-list 6938fd4d98bab03faadb97b34396831e3780aea1
```

Then create an IAM role with this trust policy (replace `ORG/REPO`):

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": { "Federated": "arn:aws:iam::<ACCOUNT_ID>:oidc-provider/token.actions.githubusercontent.com" },
    "Action": "sts:AssumeRoleWithWebIdentity",
    "Condition": {
      "StringLike": { "token.actions.githubusercontent.com:sub": "repo:ORG/REPO:*" },
      "StringEquals": { "token.actions.githubusercontent.com:aud": "sts.amazonaws.com" }
    }
  }]
}
```

### 3 — Deploy

Open **Actions → Terraform Apply + Ansible Provision → Run workflow**.

The workflow runs two sequential jobs:

| Job | What happens |
|-----|-------------|
| **Terraform Apply** | Provisions VPC, subnets, SGs, IAM roles, EC2 instances |
| **Ansible Provision** | Waits for SSH, runs all 4 playbook phases, prints cluster access info |

The four Ansible phases:

| Phase | Hosts | What happens |
|-------|-------|-------------|
| 1 | all nodes | Swap off, kernel params, containerd, kubeadm/kubelet/kubectl |
| 2 | control-plane | `kubeadm init`, Calico CNI, join-command captured |
| 3 | workers | `kubeadm join` |
| 4 | control-plane | nginx Deployment + NodePort Service deployed to `demo` namespace |

### 4 — Verify

When the workflow completes, the last step prints:

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 Cluster is ready!
 SSH:       ssh -i <key> ubuntu@<ip>
 kubectl:   ssh ubuntu@<ip> kubectl get nodes
 nginx:     http://<ip>:30080
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 5 — Teardown

**Actions → Terraform Destroy → Run workflow**, type `destroy` to confirm.

Every pull request targeting `main` triggers:

1. `terraform fmt -check`
2. `terraform validate`
3. `terraform plan` — output posted as a PR comment (old comments replaced)
4. `tfsec` security scan — annotates the PR with findings (soft-fail)
5. `TFLint` best-practices check

## Customisation

### Change the worker count

Update the `TF_VAR_WORKER_COUNT` GitHub Variable (Settings → Secrets and variables → Actions → Variables).

### Change the Kubernetes version

```yaml
# ansible/group_vars/all.yml
kubernetes_version: "1.30"
kubernetes_apt_version: "1.30.0-1.1"
```

### Switch from Calico to Flannel

```yaml
# ansible/group_vars/all.yml
cni_plugin: "flannel"
pod_network_cidr: "10.244.0.0/16"
```

Then add the Flannel manifest URL to `all.yml` and a corresponding task in the `control_plane` role.

## State Backend

State is stored in S3 with DynamoDB locking. Update `terraform/providers.tf` with your bucket and table before pushing.

```hcl
backend "s3" {
  bucket         = "your-tfstate-bucket"
  key            = "k8s-cluster/terraform.tfstate"
  region         = "us-east-1"
  dynamodb_table = "tf-locks"
  encrypt        = true
}
```

> Workers are in private subnets — outbound traffic routes through NAT Gateway.  
> The NAT GW incurs cost even when idle. Run **Terraform Destroy** when not in use.
